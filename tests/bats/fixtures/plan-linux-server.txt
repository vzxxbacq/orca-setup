orca-setup plan (read-only; nothing is changed)
Device: ubuntu 24.04 x86_64, package manager: apt, desktop: no, Orca CLI: orca-ide (in the orca-server container)
Pairing role: server (detected: none); accepts runtime pairings, never saves environments
sudo: present; --apply runs only the sudo commands listed below as root
Orca server in Docker (--apply --role server; README section 6.7):
  address  203.0.113.10 (advertised to clients)
  publish  203.0.113.10:6768 (the pairing address); port 6768 is not reachable on this host's other addresses
  workdir  ~/orca (projects/ and workspaces/; Orca's workspace directory is ~/orca/workspaces)
  host     only Docker Engine is installed here; Orca, its CLI and every agent run in the container
Docker Engine (--apply):

  present  ca-certificates
  present  gnupg

           download https://download.docker.com/linux/ubuntu/gpg, require fingerprint(s) 9DC858229FC7DD38854AE2D88D81803C0EBFCD88

           sudo install -m 0644 <verified key> <sandbox>/apt/keyrings/docker.gpg

           until your next login, setup.sh reaches Docker through "sg docker" (no password, no sudo)

Image (--apply):
  pull     ghcr.io/vzxxbacq/orca-server:main and lock its digest in ~/.config/orca-setup/docker/image.lock
           re-runs keep the locked digest; only --upgrade-image pulls a newer one
Container (--apply):
  check    the pairing role, read-only inside the image, before the container starts
  write    ~/.config/orca-setup/docker/compose.yaml
           orca-server: user 1000:1000, home ~ from ~/.local/share/orca-setup/home, host name fakehost,
           read-only root filesystem with a tmpfs /tmp, restart unless-stopped, no sudo and no Docker inside
  network  the compose project's bridge network; only port 6768 is published, on 203.0.113.10 alone
           Docker's bridge networking turns on IPv4 forwarding and adds its own iptables rules; when it turns
           forwarding on itself it also sets the iptables FORWARD policy to DROP (README section 8)
  start    docker compose up --detach (when not running as rendered); wait until `orca-ide status` in it reaches the runtime
  orca     skills and settings inside it: docker exec orca-server /opt/orca-setup/setup.sh --apply --role server
  pairing  setup.sh never creates or prints a pairing link; pair clients from a terminal (README section 3.3.2)
Optional modules (add to --apply):
  --power         Use sudo to mask the systemd sleep targets; remind you of the BIOS power-loss setting. [selected]
    skip: systemd is not the init system here (a container?), so there are no sleep targets to mask
  --containers    Install Docker Engine from Docker's apt repository if missing; add you to the docker group.
  --apple         macOS only: skipped on Linux with a notice.
  --android       Install Android platform tools if missing.
  --media         Install PDF/media processing helpers if missing. [selected]
    built into the orca-server image; nothing to install on this host
  --agent-gemini  Install the Gemini CLI if missing (optional; not usable with personal accounts).
  --gpu           Report the NVIDIA GPU, driver, nvidia-smi and CUDA toolkit (detection only; never installs).
Authentication (interactive, run on their own):
  --auth-gh       GitHub device-code login: open https://github.com/login/device on any device and enter the code gh shows; an existing valid login is kept.
  --auth-codex    Add a Codex account to this host's Orca using device authentication.
  --auth-claude   Add a Claude account to this host's Orca (interactive), unless one is selected.
  --auth-agy      Start agy to sign in to Google; over SSH it prints a URL to open elsewhere and asks for the code. Needs an unlocked Secret Service keyring to keep the session.
  --auth-linear   Print Linear's API settings URL (open it on any device); read a key without echoing or logging it.
  --check         Show baseline and authentication readiness, without printing credentials.
Existing installations and user configuration are preserved. SSH is never configured.
